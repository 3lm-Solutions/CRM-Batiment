BÂTIFLOW CRM — COMMENT LANCER LE CODE (Windows / PowerShell)
=============================================================
Version du 28/10/2026 (c) — une seule migration Prisma (0_init), pnpm 12

Dans ce guide, remplacez <DOSSIER> par l'endroit où vous avez décompressé les zips, par exemple :
  C:\Users\gara2\Downloads\new CRM\Nouveau dossier
  → backend  = <DOSSIER>\backend
  → frontend = <DOSSIER>\frontend

RÈGLES D'OR
- Toujours « pnpm », jamais « npm » (ni « pnmp »)
- Une commande par ligne, attendre la fin avant la suivante
- Deux fenêtres PowerShell : n°1 = backend, n°2 = frontend


══════════════════════════════════════════════════════════════
1. PRÉREQUIS (une seule fois sur le PC)
══════════════════════════════════════════════════════════════
    node -v                 → doit afficher v22.x
    npm install -g pnpm     (seule fois où on utilise npm : pour installer pnpm)
    pnpm -v
- PostgreSQL 16 installé et démarré (port 5432)
- Navigateur : Chrome ou Edge (la dictée vocale ne marche pas sous Firefox)


══════════════════════════════════════════════════════════════
2. FICHIER backend\.env (une seule fois)
══════════════════════════════════════════════════════════════
Copier backend\.env.example en backend\.env, puis remplir au minimum :
    DATABASE_URL=postgresql://postgres:VOTRE_MOT_DE_PASSE@localhost:5432/crm_batiment_test
    JWT_SECRET=une-longue-chaine-aleatoire
    APP_URL=http://localhost:5173
Facultatif (l'application marche sans, en mode réduit) :
    Emails sortants : MAIL_HOST, MAIL_PORT, MAIL_USER, MAIL_PASS, MAIL_FROM
    IA (Groq)       : OPENAI_API_KEY=gsk_…
                      OPENAI_BASE_URL=https://api.groq.com/openai/v1
                      OPENAI_MODEL=openai/gpt-oss-20b
                      OPENAI_VISION_MODEL=qwen/qwen3.8-27b
    Emails entrants : IMAP_HOST=imap.gmail.com, IMAP_USER, IMAP_PASS, IMAP_SUBJECTS=devis,demande
Attention : jamais de « // » devant une valeur ; ne jamais coller une vraie clé dans une conversation.
Le frontend n'a pas besoin de .env en local.


══════════════════════════════════════════════════════════════
3. PREMIÈRE INSTALLATION — BACKEND (fenêtre n°1)
══════════════════════════════════════════════════════════════
    cd "<DOSSIER>\backend"
    pnpm install
    pnpm db:reset
        → crée la base si besoin et applique 0_init
        → « Are you sure? » : répondre y (base neuve uniquement : efface tout !)
    pnpm db:seed
        → crée l'entreprise, le catalogue et les 6 comptes (affichés à l'écran)
    pnpm prisma migrate status
        → « 1 migration found » + « Database schema is up to date! »
    pnpm build
        → doit finir sans erreur

Si « pnpm install » affiche ERR_PNPM_IGNORED_BUILDS :
  le fichier backend\pnpm-workspace.yaml est fourni et autorise les bons paquets ;
  lancez alors :  pnpm rebuild   puis   pnpm install
  (Si « pnpm approve-builds » vous propose une liste : appuyer sur « a » pour tout cocher,
   puis Entrée — ne pas valider une liste vide, sinon tout est refusé.)


══════════════════════════════════════════════════════════════
4. PREMIÈRE INSTALLATION — FRONTEND (fenêtre n°2)
══════════════════════════════════════════════════════════════
    cd "<DOSSIER>\frontend"
    pnpm install
Si ERR_PNPM_IGNORED_BUILDS (esbuild) :
    pnpm rebuild
    pnpm install
(le fichier frontend\pnpm-workspace.yaml est fourni)


══════════════════════════════════════════════════════════════
5. LANCER L'APPLICATION (tous les jours)
══════════════════════════════════════════════════════════════
Fenêtre n°1 :
    cd "<DOSSIER>\backend"
    pnpm dev
  → attendre « Nest application successfully started »
Fenêtre n°2 :
    cd "<DOSSIER>\frontend"
    pnpm dev
  → « Local: http://localhost:5173/ »
Navigateur : http://localhost:5173
Arrêter : Ctrl+C dans chaque fenêtre.


══════════════════════════════════════════════════════════════

Données d'exemple (clients, devis, chantiers, prospects) — backend arrêté :
    pnpm demo:exemples
    pnpm dev


══════════════════════════════════════════════════════════════
7. VÉRIFIER QUE TOUT MARCHE (tests)
══════════════════════════════════════════════════════════════
Backend (backend arrêté) :
    pnpm build
    pnpm test          ← tests unitaires
    pnpm test:e2e      ← tests complets sur la base (celle de DATABASE_URL dans .env)
  → Les tests e2e utilisent les comptes du seed (pnpm db:seed fait avant).
  → Ils créent puis suppriment leurs propres données « e2e-… » : à lancer sur la base
    de test (crm_batiment_test), jamais sur une base avec de vraies données.
  → Aucun vrai email n'est envoyé pendant les tests.
  → Le message « ExperimentalWarning: VM Modules » est normal (nécessaire pour Prisma 7).
Frontend :
    pnpm build


══════════════════════════════════════════════════════════════
8. APRÈS UNE MISE À JOUR (nouveau zip copié par-dessus)
══════════════════════════════════════════════════════════════
Garder votre backend\.env, puis :
Backend :
    pnpm install
    pnpm db:deploy          ← applique les nouvelles migrations, n'efface rien
    pnpm prisma generate
    pnpm build
    pnpm dev
Frontend :
    pnpm install
    pnpm dev


══════════════════════════════════════════════════════════════
9. LA BASE DE DONNÉES
══════════════════════════════════════════════════════════════
- Une seule migration : prisma\migrations\0_init (toute la base)
- Migration fournie dans un zip          → pnpm db:deploy
- Vous changez vous-même schema.prisma    → pnpm db:migrate --name nom_court
- Voir les données dans le navigateur     → pnpm db:studio
- pnpm db:reset EFFACE TOUTE LA BASE : seulement pour une base neuve ou de test
  (avec Prisma 7, relancer ensuite pnpm db:seed : le reset ne le fait plus tout seul)
- Ne pas utiliser « pnpm prisma db push » sur une base qui a des migrations
- Message « Update available prisma 8.x » → ignorer, rester en version 7


══════════════════════════════════════════════════════════════
10. ERREURS FRÉQUENTES
══════════════════════════════════════════════════════════════
ERR_PNPM_IGNORED_BUILDS                → pnpm rebuild puis pnpm install (voir §3 / §4)
« Unknown command: prisma »            → vous avez tapé npm au lieu de pnpm
« pnmp n'est pas reconnu »             → faute de frappe : pnpm
Ligne qui commence par « >> »          → PowerShell attend la suite : Ctrl+C et taper
                                         une commande à la fois
« Cannot find module dist/main »       → pnpm build, puis pnpm dev
« Can't reach database server »        → PostgreSQL arrêté ou DATABASE_URL faux
« P1000 Authentication failed »        → mauvais mot de passe dans DATABASE_URL
« Base de données pas à jour » / 500   → pnpm db:deploy puis redémarrer le backend
« Following migrations have not yet been applied » → pnpm db:deploy
« Drift detected » / demande de reset  → répondre N, ne rien effacer, m'envoyer le message
« EADDRINUSE :3000 » ou « :5173 »      → l'application tourne déjà dans une autre fenêtre
Page blanche / « Network Error »       → le backend n'est pas lancé (fenêtre n°1)
Aucun compte pour se connecter         → pnpm db:seed
IA : « IA_NON_CONFIGUREE »             → OPENAI_API_KEY absent du .env
Dictée : bouton absent / indisponible  → Chrome ou Edge, et autoriser le micro
Avertissement « The "pnpm" field… »    → sans conséquence
Tests : « Cannot find module './internal/class.js' » → zip trop ancien : prendre le zip du
                                         28/10 (c) (package.json + test\jest-e2e.json corrigés)

RÉCAPITULATIF
══════════════════════════════════════════════════════════════
1re fois  backend  : pnpm install → pnpm db:reset → pnpm db:seed → pnpm build → pnpm dev
1re fois  frontend : pnpm install → pnpm dev
Tous les jours     : pnpm dev (backend) + pnpm dev (frontend) → http://localhost:5173
Mise à jour        : pnpm install → pnpm db:deploy → pnpm prisma generate → pnpm dev
